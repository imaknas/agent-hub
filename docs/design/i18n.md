# Multilingual agent-hub: evals first, then translate everything

> agent-hub session · 2026-10-30 · r2. Owner's order: **define the evals first, translate everything, make it multilingual.**
> Today every comment, doc, CLI message, model prompt, agent rule and machine format is Traditional Chinese (~8,400 lines in
> 245 files). After this work the repo is English, and an instance chooses its languages; this deployment stays Chinese.

## Goal and the one rule

- The repo reads in English: code, comments, docs, prompts, templates, contracts.
- An instance picks **two languages**: `language.ui` (what the platform shows the owner: CLI output, status page, alerts,
  digest/todo headings) and `language.content` (what models and agents write: STATE.md, memory notes, digests,
  reflections, letters). Default `en` for both; this instance sets both to `zh-Hant`.
- **The rule: for an instance on `zh-Hant`, nothing observable changes** unless an eval below says the change is within
  noise, or the owner approved that specific difference. Translation is not allowed to be a silent behavior change.

## What changes, by kind of text

| Kind | Where | How it becomes multilingual | Risk |
|---|---|---|---|
| Comments, docstrings, design docs, AGENTS.md, known-issues | everywhere | translated once to English; no runtime effect | none (tests + lint prove it) |
| Owner-facing messages | CLI, doctor, status page, alerts, merge-branch, hubbus notices, todo.md/digest headings | gettext-style: English source string in code, `_("…")`; catalog `locales/zh-Hant.json` | wording drift; tests that match Chinese text |
| Model prompts | librarian, consolidate, reflect-week, mailbox, lease handover, propose | English prompt files in `templates/prompts/<point>.md` with an explicit "write in {content_language}" | **output quality and language** |
| Agent rules | `templates/agent-instructions.md`, `templates/rules/*`, `mcp-instructions.md`, `AGENT.md` | English text + content-language directive | **agent behavior in every project** |
| Machine formats | STATE.md `## 待辦` + `〔owner\|agent\|待定〕`, todo.md blocks, digest sections, hubbus fields | a second (English) token set; readers accept both, writers follow `language.content` (`state-todo.v2`, `todo-md.v2`) | **Muninn reads them** |

## The evals (built and run before anything is translated)

### E0 — static checks (every commit, in the test gate)

- **No CJK outside allowed places**: ratchet test over tracked files; allowed: `locales/`, test fixtures that are deliberately
  Chinese (golden outputs, zh test data), the private-names list. Count may only go down; ends at zero.
- **Catalog completeness**: every `_()` msgid in code has a `zh-Hant` entry; no stale entries; placeholders (`{name}`)
  identical between msgid and msgstr.
- **Contract examples**: v1 and v2 examples of each machine format validate; v1↔v2 conversion round-trips.

### E1 — golden outputs of the mechanical paths (no model)

Characterization tests captured from the **current** code and committed before any message moves (same pattern as
`tests/fixtures/llm-golden.json`). Each runs with a fixed clock, a temp instance and fixtures:

- `agenthub doctor` (healthy and broken variants), `agenthub --help`, `schedulectl list`, `agenthub modules`
- status page HTML (`gen-status-page.py`), alert texts (`alert.py` new/reminder/recovered)
- `gen-todo.py` → todo.md; `check-memory-gaps.py --apply` block; digest section writers
- hubbus: inbox/hook injection text, `merge-branch` success and each failure stage, `commit_title` messages
- `sync-local-setup` managed block (instructions file), `registry.py check` errors, `config-check` errors

Pass: with `language.ui = zh-Hant`, output is **byte-identical** to the golden (except differences listed in the PR and
approved). With `en`, output has no CJK and a reviewed English golden is added.

### E2 — judgment points (model calls): same decisions, right language

The evaluator infrastructure in `evaluators.md` (recorder, replay, `HUB_EVAL_REPLAY`) is not built yet. E2 does **not**
wait for it: it freezes each point's prompt **inputs** (not a full session replay), runs both prompt versions through
`llm.py` (same sealing as production), and scores mechanically. What it builds (`bin/evals/`, case storage, scorers) is
the first piece of that design and is kept compatible with it.

Points: `librarian-state(-edits)`, `librarian-index(-edits)`, `librarian-todo-format`, `consolidate`, `reflect-week`,
`mailbox-propose`, `lease-handover`. (`agent-job`, `login-check` have job-owned or trivial prompts; `mailbox-escalation`,
`mailbox-conversation`, `lease-session`, `lease-work` go to E3.)

- **Cases** live in the platform's eval directory (`hubconf.evals_dir()`, hub.json `evals_dir`; 0700, outside git,
  `backup.covers()` false; unset = nothing recorded):
  - librarian points: **recorded from production**. Each night `librarian.py` saves, per project, the raw builder
    arguments (memory diff, handoffs, dangling refs), the prompts as rendered that night (= the `old` arm, exactly), a
    snapshot of the memory copy at that commit (what the agent could read), and the outcome (STATE.md after, decision).
    Same for index.md. Kept 60 days. Reconstructing past nights from git is not attempted.
  - consolidate: generated on demand (`--dry-run --project` at a base commit); reflect-week: the stored weekly stats;
    propose/handover: synthetic but realistic letters/conversations.
  - ~8 cases per point (reflect-week: what exists).
- **Runs**: real HOME (the model login lives there), but `AGENT_HUB_STATE` and a temp `hub.json` `bus_dir` point at the
  eval dir, so eval calls never reach the real bus or status page. Agent-shape points run on a fresh copy of the snapshot
  each time; what is scored is the file diff after. Re-rendering pins the case's date and names.
- **What `new` means for librarian-state**: the new prompt *and* the new (English) `AGENT.md`/rules in the snapshot,
  which is production after step 5. If it fails, swap one at a time to find which.
- **Arms**: `old` = current Chinese prompt; `new` = English prompt with `content_language = zh-Hant`; also `new-en` =
  English prompt with `content_language = en` (for other users; scored on validity + language only). Same model, same
  sealed call path (`llm.py`), k = 3 runs per arm per case.
- **Scores (mechanical, no judge model)**:
  - schema-valid rate; contract-valid rate (`check-state-todo.py`, consolidate's own checks)
  - output language: share of CJK in free-text fields ≥ 0.6 for zh-Hant, = 0 for en (thresholds set from the `old` arm)
  - script: zero Simplified-only characters for zh-Hant (这、说、对、时、为、国、会、们、个、来…), and full-width punctuation
    at the `old` arm's rate — an English prompt asking for Traditional Chinese is exactly where a model slips
  - decision agreement: `state_updated` / changed-or-not, to-do item set (Jaccard), labels for decide-type fields
  - content similarity of written text vs `old` (character n-gram), reported, not gated
- **Noise floor**: `old` vs `old` across its own k runs. **Pass** = `new` vs `old` agreement not worse than the noise floor
  by more than its 90% bootstrap interval, and validity/contract/language rates not lower. Fail → fix the prompt, rerun.
- Budget: usage is not the constraint (owner, 10-30); wall-clock and rate limits are. `new-en` runs at k = 1 (it is scored
  on validity and language only); full runs go in the background, not during the nightly jobs, and stop on rate limits.
- Scorers reuse the shadow-mode ones (`edits.apply`, `edits.check_markers`, `check-state-todo.py`, SequenceMatcher,
  same decision). A pilot (old vs old, k = 3) decides whether to-do items need fuzzy matching before Jaccard.

### E3 — agent rules in a throwaway project (headless scenarios)

The rules every project agent reads change language, so a small scenario suite runs a headless agent in a disposable
project (the propose sandbox: a throwaway worktree, platform applies nothing) with **old** vs **new** instructions:

1. "Note what you just decided" → a memory note exists, in the content language, in the right place.
2. "Add a to-do for the owner" → STATE.md to-do line passes `check-state-todo.py`.
3. "Ask agent-hub for X" → uses `agenthub send` with the right flags (captured, not delivered).
4. A letter in the inbox → handled per rules (ack/reply/done shape).
5. "Commit this" in a `commits: conventional` project → title passes `commit_title`.

k = 3 per arm; pass = new arm ≥ old arm on each scenario's checks. The `old` instructions are `templates/` at 13b6788
(`git show`), so the old arm can run before anything is translated.

## Language settings and catalogs

- `hub.json`: `"language": {"ui": "zh-Hant", "content": "zh-Hant"}`; schema enum starts as `en`, `zh-Hant`; unknown → config
  check error. `hubconf.lang_ui()` / `lang_content()`; shell gets them from `hubpaths.sh`.
- The `zh-Hant` catalog is built **mechanically**: msgid = the new English string, msgstr = the current Chinese string
  verbatim. That is what makes E1's byte-identity possible; nobody re-translates back into Chinese by hand.
- Tests: harnesses run with the default (`en`); assertions on Chinese messages move to the English msgid as each file is
  converted. Chinese output is covered by the E1 goldens (run with `zh-Hant`) and catalog completeness.
- `bin/i18n.py`: `_(msgid, **kw)` looks up `locales/<ui>.json`, falls back to the English msgid, then `.format(**kw)`.
  Standard library only (the watchdog keeps its own tiny copy). Shell: `bin/i18n.py msg "<msgid>" k=v …`.
- Prompts: `templates/prompts/<point>.md` in English; `{content_language}` filled from settings; owner/assistant names
  keep using `fill_names`.
- Agent rules: English templates; `sync-local-setup` adds one line naming the content language.

## Machine formats: both token sets, the writer follows the content language

Owner decision (10-30): the to-do format is bilingual; for this instance Chinese stays.

- The to-do block has two token sets. zh-Hant (today, `state-todo.v1`): heading `## 待辦`, tags `〔{owner}|agent|待定〕`, key
  marker `(等 {owner}:<key>)`, empty `- (無)`. en: heading `## To-do`, tags `[{owner}|agent|tbd]`, key marker
  `(waiting on {owner}: <key>)`, empty `- (none)`. The owner tag text still comes from settings (e.g. `[Alex]`).
  `todo-md` headings likewise.
- **Every reader accepts both sets, whatever the setting** (`gen-todo.py`, registrar, `check-state-todo.py`, consolidate's
  checks, Muninn). That is `state-todo.v2` / `todo-md.v2`: v1 plus the English set; no file changes version.
- **Writers emit the set of `language.content`** (librarian prompts, templates, `gen-todo.py` headings by `language.ui`).
- This instance stays on zh-Hant: no STATE.md conversion, E1 goldens unchanged, nothing Muninn has to change now. Muninn
  needs the v2 readers only before it reads an English instance; tell it when v2 lands (info, not a gate).

## Order

1. E0 checks (ratchet starts at today's count), E1 goldens captured from current code — committed before any change.
2. E2/E3 harness (`bin/evals/`), cases frozen, `old` arm and noise floor recorded.
3. `language` settings + `bin/i18n.py` + catalog; move owner-facing strings behind `_()` file by file, E1 green at each step.
4. Translate comments, docstrings, docs (no behavior; tests + lint).
5. Prompts and agent rules to English; run E2/E3; iterate until pass.
6. Contract v2: readers accept both token sets; writers follow `language.content` (this instance: unchanged); tell Muninn.
7. Ratchet reaches zero CJK outside `locales/` and fixtures; README drops the "docs are in Chinese" note.

## Decided

- To-do tokens: bilingual, writer follows the content language, this instance stays Chinese (owner, 10-30; above).
- STATE.md headings beyond the to-do block stay in the content language; only the to-do block is machine format.
- Eval budget: approved without a cap (owner, 10-30).
