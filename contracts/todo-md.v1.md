# 契約:todo.md(跨專案待辦)v1

產生者:`bin/gen-todo.py`(librarian 每晚,零 LLM),之後 librarian 在檔尾補 memory 缺口區塊。
讀的人:Knas、owner 的個人助理(讀「只有 owner 能做」以外的段落當外部待辦)。

## 版面

1. 第一行固定是版本標記 `<!-- contract: todo-md v1 -->`(2026-10-22 起;更早的檔沒有,讀成 v1)。
2. `# 跨專案待辦`,接著 `>` 開頭的說明行(不是待辦)。
3. 三個負責人段落,**標題文字固定**,順序固定:

```heading owner
## 只有 Knas 能做
## 待定(需要先做決定)
## agent 可以做
```

4. 每個段落底下:`### <專案名稱>` 小標題,底下一行一項 `- [ ] <文字>`;沒有項目就是一行 `(無)`。
   「只有 Knas 能做」段落開頭可能有一行 `> 另有 N 項已登記在 Muninn…`(已經登錄成任務的不列)——是說明,不是待辦。
5. 可能還有 `## 格式問題(這些專案的待辦沒被收進來)`(`- ` 開頭,不是 `- [ ]`)。
6. 檔尾可能有 `<!-- memory-gaps:begin -->` … `<!-- memory-gaps:end -->` 區塊(`## memory 沒在記的專案`)。

## 規則(讀的人照這些 regex 解析)

```regex project
^### (\S+)\s*$
```

```regex item
^- \[ \] (.+)$
```

讀的人只取「負責人段落裡、`### 專案` 底下」的 `item`;其他行一律略過。

## 版本

加段落或說明行不升版(讀的人本來就略過不認得的行);改三個負責人標題、改 item/project 的格式要升版,
產生者同時輸出 v1、v2 兩份檔直到讀的人換完。
